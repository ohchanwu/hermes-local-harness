## 4. Conditional provider feasibility and architecture

M2 is a small, separately authorized feasibility stage, not an adapter commitment. Prefer a repository-owned, uniquely named provider plugin through documented `create_client` / `external_process` hooks [S2–S5]. Determine the unique name in that approved stage; do not hijack `claude-code`, replace `anthropic` or assume the proposed provider already exists. Hermes remains the agent and the official unmodified Claude runtime owns sign-in. Public SDK source/interfaces may be evaluated offline under bounded authority; actual SDK/account use requires its applicable prerequisites and must not be assumed to be a transparent raw-model API.

Anthropic's SDK overview restricts third-party offerings of consumer Claude login/rate limits [S6]. Its legal/compliance documentation separately allows end users to sign in to the unmodified Claude Code binary themselves, including hosted-binary contexts [S7]. Distinguish the documented restrictions from their applicability to the intended personal/local use. These statements neither authorize arbitrary wrappers nor prohibit every personal local use. Non-inference preparation may proceed under future explicit local authority without a mandatory external clarification/approval gate; no terms exemption or Anthropic approval is implied. Before a model trial, resolve concrete applicable constraints and retain §3's exact bounded authorization, official runtime-owned auth and proportional included-allowance boundary. Never collect credentials, copy/replay subscription tokens, spoof client identity, modify the Claude binary or bypass billing controls.

Feasibility must establish all of the following before promising implementation:

- **One authoritative tool executor.** Hermes owns tool permissions, approval decisions, board/repository/worktree/task pins and actual tool audit records. The Claude subprocess must not independently run filesystem/shell tools or silently start a second agent with wider authority. Use only supported controls to prevent that execution while carrying structured tool requests back to Hermes. If the runtime cannot do this, reject this transparent-provider architecture; a shell wrapper is not an equivalent integration.
- **Protocol translation.** Preserve system/user/assistant semantics; structured tool-call IDs, names, arguments and matched results; parallel-call ordering as supported; errors and completion reasons; streaming boundaries and partial output. Validate malformed/duplicate IDs and arguments without executing invented tools. Exercise the real Hermes executor and continuation, not a transcript stub.
- **Lifecycle.** Handle cancellation during startup and streaming, startup races, process death, timeouts, cleanup and quota errors without duplicate requests/tools or orphan processes. Resume/continuation is scoped to the correct profile, session, task, role and worktree; stale processes/sessions cannot attach to a new task.
- **Independent state.** Isolate orchestrator, worker and reviewer sessions, mutable runtime state and private deliberation. Preserve exact reviewer assignment and evidence access. Using Opus for every role does not merge their authority or remove independent same-card review.
- **Every model-using path.** Inventory delegated agents and auxiliary calls, including compression, vision and other configured helpers. Verify requested/effective selection and truthful attribution; exclude an optional unsupported path from the Claude-only workflow with explicit limitation. A required missing path blocks full-cutover readiness. Never quietly use an OpenAI/Zai/API fallback for a helper while advertising Claude-only operation; this is not a global provider ban. The historical helper disk/session mismatch remains selection-correctness evidence, not proof of billing or a reason to search for absent accounts.
- **Honest attribution.** Report verified effective provider/model and available usage metadata. Unknown usage stays unknown, not zero or free. Account-side evidence remains necessary for included-pool billing; a plugin's reported cost is not a receipt.
- **Requested-provider and error correctness.** Hermes documents that `create_client` exceptions can fall back to a standard HTTP client [S2]; the historical negative constructor observation is retained. It is not proof of a charge and does not automatically reject the architecture. Test supported construction/startup/runtime/quota behavior for the requested effective provider, truthful attribution and explicit failure in a bounded Claude-only task, without silent substitution. Use narrow route spies/error tests; no universal no-HTTP/no-paid-route proof is an architecture gate. If required selection correctness cannot be delivered through supported interfaces, report that limitation rather than patch core or claim success.

No Hermes fork, installed-source edit, monkey patch, modified runtime or core-patch dependency is in scope. Do not hide effective-provider substitution in an explicitly Claude-only task. An infeasible result is useful evidence; it is not permission to silently enlarge the architecture or implement a billing bypass.
